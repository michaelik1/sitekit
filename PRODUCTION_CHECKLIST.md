# Контрольный список перед публикацией

## Обязательно

- [ ] Укажите реальный домен в `NUXT_PUBLIC_SITE_URL`.
- [ ] Укажите рабочий адрес редакции в `NUXT_PUBLIC_CONTACT_EMAIL`.
- [ ] Замените ролики с `placeholder: true` на настоящие `video.mp4` и обновите `duration`.
- [ ] Проверьте название, сезонный блок и подпись проекта в `content/site.json`.
- [ ] Выполните `npm ci && npm run check` на машине с доступом к npm registry.
- [ ] Запустите контейнер и убедитесь, что `/api/health` возвращает успешный ответ.
- [ ] Проверьте canonical, sitemap и RSS уже на итоговом домене.

## Reverse proxy

- [ ] Завершайте TLS на Traefik, Caddy или Nginx.
- [ ] Передавайте `Host`, `X-Forwarded-Host`, `X-Forwarded-Proto` и реальный IP клиента.
- [ ] Не публикуйте порт Nuxt напрямую в интернет.
- [ ] Ограничьте размер тела запроса: сайт не принимает пользовательские загрузки.
- [ ] Добавьте внешний rate limit только там, где он действительно нужен; публичный контент должен нормально индексироваться.

## Контент

- [ ] У каждой опубликованной статьи есть уникальные `title`, `summary`, `description` и обложка.
- [ ] Даты публикации не стоят в будущем.
- [ ] Изображения оптимизированы в WebP/AVIF, если это фотографии; SVG оставлены для схем и иллюстраций.
- [ ] У видео есть понятный постер, корректная длительность и субтитры, когда присутствует речь.
- [ ] Ссылки и фактические советы проверены редактором перед публикацией.

## Наблюдение после запуска

- [ ] Проверяется доступность главной и `/api/health`.
- [ ] Логи reverse proxy и приложения имеют ротацию и не содержат лишних персональных данных.
- [ ] Резервируются `content/`, переменные окружения и конфигурация reverse proxy.
- [ ] После обновления запускается `npm run check`, затем выполняется атомарная замена контейнера.
